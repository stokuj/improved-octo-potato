# TypeScript Migration — Design Spec

**Date:** 2026-05-19
**Branch:** feature/user-inventory (to be executed on a new branch)
**Scope:** SvelteKit frontend only — backend unchanged

---

## Goal

Convert the frontend from JavaScript to TypeScript. Primary motivation: project cleanliness and long-term maintainability. Secondary benefit: API type safety via `openapi-typescript` (FastAPI schema → generated types → compile-time errors on schema drift).

---

### Files changed

| `jsconfig.json` | Rename → `tsconfig.json`, add `"include"` |

## Type Strategy

### Two-file pattern

`api.d.ts` — generated, never edited by hand:
```ts
// produced by: npm run gen:types
// contains deeply nested path/component types from FastAPI openapi.json
```

`src/lib/types.ts` — hand-maintained aliases, imported everywhere:
```ts
import type { components } from './api.d.ts'

export type CraftResult   = components['schemas']['CraftResult']
export type CraftNode     = components['schemas']['CraftNode']
export type InventoryItem = components['schemas']['InventoryItem']
export type ItemDetail    = components['schemas']['Item']
export type PricePoint    = components['schemas']['PricePointRead']
// add more as needed
```

Components import **only from `$lib/types`**, never directly from `api.d.ts`. When FastAPI renames a schema, one alias line changes in `types.ts`.

### JSDoc removal

Every `/** @typedef {...} */` block is removed. The file gets an import instead:
```ts
import type { CraftResult } from '$lib/types'
```

### Known friction points

- `auth.svelte.ts` — `$state` rune may need explicit generic: `$state<User | null>(null)`
- `grades.ts` — object literal needs `Record<string, string>` or a const enum
- `mockData.ts` — mock shapes must match generated types exactly

## Regenerating Types

Types are committed to the repo. Workflow when backend schema changes:

```bash
# backend must be running
npm run gen:types        # overwrites src/lib/api.d.ts
npm run check            # verify no new type errors
git add src/lib/api.d.ts src/lib/types.ts
git commit -m "chore: regenerate api types"
```

`package.json` scripts:
```json
"gen:types": "openapi-typescript http://localhost:8000/openapi.json -o src/lib/api.d.ts",
"check": "svelte-kit sync && svelte-check --tsconfig ./tsconfig.json"
```

---

## Execution Order

All changes land in a single commit. Execute in this order to minimise cascading errors:

1. Install `openapi-typescript` dev dependency
2. Add `gen:types` script to `package.json`
3. Start backend, run `npm run gen:types` → produces `src/lib/api.d.ts`
4. Write `src/lib/types.ts` with aliases
5. Rename `jsconfig.json` → `tsconfig.json`, update `package.json` `check` script
6. Rename all `src/lib/*.js` → `.ts`
7. Add `lang="ts"` to all `.svelte` files
8. Remove JSDoc typedefs, add `import type` from `$lib/types`
9. Run `npm run check`, fix any type errors surfaced
10. Commit

---

## Success Criteria

- `npm run check` passes with zero errors
- CI `frontend.yml` green
- No JSDoc `@typedef` blocks remaining in source files
- `src/lib/api.d.ts` committed and up to date with current FastAPI schema
