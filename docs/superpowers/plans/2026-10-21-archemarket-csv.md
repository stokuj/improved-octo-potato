# ArcheMarket CSV Rebuild Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the dead JSONL/bot price pipeline with manual ArcheMarket CSV uploads (`listings.csv`, `market.csv`) and a `/market` page (14-day chart, cheapest offers, today-vs-7-days table). Remove dead modules, freeze crafting and inventory, and give the repo a symmetric domain layout.

**Architecture:**
- The backend keeps FastAPI + SQLModel + fastapi-users. `app/core` holds the shared plumbing, `app/auth` holds users and login, and `app/market` holds items, market days, listings and the CSV import.
- The import is idempotent through table keys and bulk upserts, one transaction per file.
- The frontend keeps SvelteKit 5 + ECharts, with `lib/core`, `lib/market` and two new routes.

**Tech Stack:** Python 3.13, FastAPI, SQLModel, Alembic, asyncpg, fastapi-users, slowapi, pytest; SvelteKit 5, TypeScript, Tailwind 4, DaisyUI 5, ECharts 6, vitest, Playwright; podman compose (local), docker compose (CI), Caddy.

**Spec:** `docs/superpowers/specs/2026-10-21-archemarket-csv-design.md` (approved 2026-10-21). Read it together with this plan. Background: `docs/view.md`.

## Global Constraints

- Work on branch `feature/archemarket-csv`. Never commit to `main`, never push, never merge.
- Every commit leaves these green: `cd backend && uv run ruff check . && uv run ruff format --check . && uv run pytest`, and from Task 10 on also `cd frontend && npm run check && npm test`.
- Commit messages use `type(scope): description` (feat, fix, chore, docs, refactor, test) and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests use a real Postgres (`app_test`), no DB mocks, unique test data, and no cleanup between tests.
- Naive UTC datetimes in the DB.
- One slowapi limiter singleton (`app/core/rate_limit.py` from Task 3 on).
- All API routes under `/api`, admin at `/admin`.
- Code comments, docs and PR text in English, short.
- Domain module core file set: `models.py`, `schemas.py`, `services.py`, `router.py`, plus `admin.py` where it needs one. **Every other file starts with a one-line comment giving its reason.**
- A module never imports another module's models, only its services. FKs are allowed.
- Tests mirror `app/` (`tests/<module>/test_<subject>.py`).
- Money and volume use `bigint`. `item_grade` is the raw game int. The game day is computed at UTC+3 (Moscow, no DST).
- Frontend: `formatCurrency` from `$lib/core/currency`, `credentials: 'include'` on every fetch, API types generated by `openapi-typescript`, DaisyUI theme `night`.
- `podman compose` locally through the Makefile; `docker compose` only in GitHub CI.
- Nothing is deleted until the user has confirmed the delete list (Task 1, Step 2).

## Review Focus

1. **Windows line endings and a BOM.** The addon runs on Windows, so files may be CRLF with a UTF-8 BOM. The header must still be detected and every row parsed (test in Task 6).
2. **Junk uploads:** an empty file, a header-only file, a non-UTF-8/binary file, or a CSV with an unknown header. Each gives a per-file result with `kind=None` and a clear error, never a 500, and the other files in the request still import (test in Task 7).
3. **Large full-history files:** more than 32 767 bind parameters in one statement crash asyncpg. A generated market file with 5 000 distinct `(item, day)` rows must import (test in Task 7).
4. **Items with listings but no market data** (for example `Nonexistent Item`): they appear in `/api/market/items` with `item_type=None` and `last_day=None`, are absent from `/summary`, and `/market` shows "No market data" instead of an empty or broken chart (tests in Tasks 8 and 11).
5. **The same kind twice in one request** (two overlapping `market.csv` uploads): the second one only skips or updates, never errors on the shared keys (test in Task 7).

Pure logic with no DB. First line of the file: `# Pure parsing/validation of ArcheMarket CSV files; no DB access.`

**Files:**

**Interfaces:**
- Produces:

```python
LISTINGS_HEADER = "scan_id,captured_at,item,status,rank,unit_price_copper,listing_price_copper,stack"
MARKET_HEADER = "scan_id,captured_at,item,item_type,item_grade,status,day,daily_avg_copper,weekly_avg_copper,min_copper,max_copper,volume"
GAME_TZ = timezone(timedelta(hours=3), "MSK")   # ArcheRage server clock (Moscow, no DST)
Kind = Literal["listings", "market"]

class CsvFormatError(Exception): ...            # whole-file problem; str(e) is the reason

@dataclass(frozen=True)
class RowError: line: int; reason: str          # line = 1-based physical line number (header = 1)

@dataclass(frozen=True)
class ListingRow: line: int; scan_id: int; captured_at: datetime; item: str; status: str; rank: int
                  unit_price: int | None; listing_price: int | None; stack: int | None

@dataclass(frozen=True)
class MarketRow: line: int; scan_id: int; captured_at: datetime; item: str; item_type: int; item_grade: int
                 day: date; daily_avg: int; weekly_avg: int; min: int; max: int; volume: int

@dataclass
class ParsedFile: kind: Kind; rows: int; listings: list[ListingRow]; market: list[MarketRow]
                  skipped: int; errors: list[RowError]   # skipped = market no_answer/error lines

def game_day(captured_at: datetime, day: int) -> date        # captured_at is naive UTC
def parse_csv(data: bytes) -> ParsedFile                     # raises CsvFormatError
```

- `captured_at` is `datetime.fromtimestamp(epoch, timezone.utc).replace(tzinfo=None)`.
- Decode with `utf-8-sig`. Read with `csv.reader(io.StringIO(text, newline=""))`. The header comparison is `",".join(header_row) == …_HEADER`.
- Whole-file errors: `"empty file"`, `"not UTF-8"`, `"unknown header"`.
- The row rules are spec §2.5 *Row validation*, verbatim.

- **A file over the cap** gets `kind=None, error_count=1, errors=[{line: 0, reason: "file larger than 50 MB"}]`. The service reads at most `MAX_FILE_BYTES + 1` bytes.
- **A `CsvFormatError`** gives the same shape, with the error's reason.
- **A DB error** rolls back that file and gives the same shape, with `"database error: <exception class name>"`.
- **Market:**
  - dedup in memory by `(item_id, day)`, keeping the max `captured_at`; in-file losers count as `skipped`;
  - `INSERT … ON CONFLICT (item_id, day) DO UPDATE SET … WHERE market_day.captured_at < EXCLUDED.captured_at RETURNING (xmax = 0) AS inserted`;
  - a returned row is inserted or updated, and every surviving row not returned counts as skipped.
- **Listings:** `INSERT … ON CONFLICT DO NOTHING RETURNING 1`. Returned rows are inserted, the rest skipped.
- **Chunk size:** insert in chunks of ≤ 2 000 rows (the limit is 32 767 bind params).
- **Rows whose item failed to resolve** become row errors with the resolver's reason.
- **Invariant:** `inserted + updated + skipped + error_count == rows`.
