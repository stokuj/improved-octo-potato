# Items Page (Bag, Warehouse, House Chests) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import ArcheBag step 7d `inventory.csv` (bag + warehouse) and `chests.csv`, keep two snapshots per place, and show them on a new `/items` page: characters on the left, house chests on the right, each side with an `All` tab.

**Architecture:**
- `inventory_snapshot` gains `container` (`bag` | `bank` | `chest`) and `chest` (1–10, 0 otherwise). A place is `(container, character)` for bag and bank, `(chest, number)` for chests. Keep-two runs per place.
- Chest names live in a new `inventory_chest_name` table, one row per `(user, chest)`, because an empty name means "no change" and must outlive the two kept snapshots.
- The read API returns everything in two calls: `GET /api/inventory/characters` (each with `bag` and `bank` grids) and `GET /api/inventory/chests`. The page switches tabs client-side.

**Tech Stack:** FastAPI, SQLModel + Alembic, PostgreSQL 16, SvelteKit 2 (Svelte 5 runes), DaisyUI, vitest, Playwright.

**Spec:** `docs/ai/superpowers/specs/2026-10-23-items-design.md`

## Global Constraints

- Branch `feature/items`. Never push, merge or touch `main` without the user's request.
- Commits are `type(scope): description` and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No real character names in the repo.** The ArcheMarket retest files contain one; never copy them. Fixtures use `Alpha`, `Bravo`.
- `inventory.csv` header, exactly: `snapshot_id,captured_at,character,container,slot,item,item_type,item_grade,count,category,npc_price`
- `chests.csv` header, exactly: `snapshot_id,captured_at,character,chest,name,zone,x,y,z,slot,item,item_type,item_grade,count,category,npc_price`
- The old 8-column header is no longer accepted (`unknown header`).
- `category`, `npc_price`, `zone`, `x`, `y`, `z` are read past, never validated or stored.
- Every inventory read and write is scoped to the signed-in user. Inventory files are open to any active user.
- Import invariants: re-upload is a no-op; the newest snapshot wins; `inserted + updated + skipped + error_count == rows` per file.
- Grid is 10 columns, at most 300 slots per snapshot.
- Backend tests:
  ```
  docker run -d --rm --name pg-test -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=app_test -p 5434:5432 postgres:16-alpine
  cd backend && TEST_PG_HOSTPORT=localhost:5434 uv run pytest
  ```
  Migrations: `docker exec pg-test createdb -U postgres mig`, then `DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5434/mig uv run alembic upgrade head && ... alembic check`.

## Review Focus

1. **One `Bag` click** writes bag and warehouse under the same `snapshot_id`: both must be stored, and re-upload must skip both (Task 2, `test_bag_and_bank_share_snapshot_id`).
2. **A chest saved by two different characters** is still one chest: keep-two counts both characters' saves together (Task 2, `test_chest_keep_two_across_characters`).
3. **An older `chests.csv` uploaded after a newer one** must not rename a chest back (Task 2, `test_older_chest_name_does_not_win`).
4. **A character with only a warehouse** (the bag read failed in game) shows only the Warehouse grid, and `bag` is `null` (Task 3 `test_bank_only_character`, Task 4 `shows only the warehouse when a character has no bag`).
5. **A stale or bad `?chest=` / `?character=`** (renamed character, non-number) falls back to `All` without a request for it (Task 4, `falls back to All for unknown tabs`).
