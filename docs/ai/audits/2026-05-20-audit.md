# Audyt projektu — 2026-05-20

## Ogólna ocena

Projekt jest w dobrym stanie technicznym. TypeScript 100%, svelte-check 0 errors, testy pokrywają wszystkie główne moduły. Główne problemy to brak ochrony endpointu ingest, kilka race condition w backendzie, i braki w infra (healthchecks, security headers).

---

## CRITICAL

| # | Problem | Lokalizacja |
|---|---|---|
| C1 | `/api/ingest/prices` bez auth — data poisoning + item flooding (6000 śmieciowych itemów/min z jednego IP) | `ingest/router.py:12` |
| C2 | Race condition na `Item.current_price` — brak `SELECT FOR UPDATE` przy concurrent writes | `prices/services.py:117` |
| C3 | Auth race w frontend — `onMount` sprawdza guard zanim `checkMe()` się skończy; użytkownik niezalogowany widzi chronione strony | `ItemTable.svelte:178` |
| C4 | Rate limiter singleton vs. 2 workery w prod — każdy worker ma własny licznik, limit faktycznie = 120/min | `docker-compose.prod.yml:23` |
| C5 | Caddy startuje bez `service_healthy` — może routować ruch zanim backend skończy migracje alembic | `docker-compose.prod.yml:58` |

## Priorytety napraw

1. **C1** — API key / token na ingest endpoint
2. **C3** — Auth guard: zamienić `onMount` na `$effect` z warunkiem `!user.loading`
3. **I1 + I2** — `ON CONFLICT DO NOTHING` w profile i user_items
4. **C5** — Healthcheck na backend + `condition: service_healthy` w Caddy
5. **C4** — Redis-backed rate limiter lub powrót do 1 workera
6. **I9** — Login: `URLSearchParams` zamiast `FormData`
7. **I10** — Error handling przy inventory PUT
8. **I15** — Security headers w Caddyfile
9. **I16–I18** — Brakujące testy
